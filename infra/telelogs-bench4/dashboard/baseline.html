The gain is C4 (+31) and C1 (+26); the cost is C3 (−15), which is now the ladder's fallback and absorbs every case the three magnitude rules decline. 27 of C3's 31 errors are cases where the data cannot separate C3 from C1 even in principle — the comparison C3 asserts is counterfactual and a single drive test never observes it.

What changed to get here

Only the residual tie-break. Same weights, same compiled ReAct program, same six tools, same cost. The four causes with no exact criterion used to be decided by asking whether each phenomenon was present; they are now decided by asking how much of it is present.

Before · presence

1min_diff ≥ 142.5 → C3 73.0%
2a mod-30 pair exists → C6 78.0%
3a gap ≥ −3 dB exists → C4 79.0%
4a row below the lobe exists → C1 77.1%
5otherwise C385.7%

A flat 73–79% band. When three phenomena co-occur the fixed order is a weighted coin toss — 29.3% correct.

Now · magnitude

0a below-lobe row with RSRP ≤ −90 → C1 (unchanged)—
1equal_residue_pair_count > 2 → C6 100%
2noncolocated_gap_…_count > 2 → C4 99.1%
3deepest_below_lobe_deficit_deg > 2.5 → C1 63.3%
4otherwise C395.1%

Two rules become essentially exact. All the remaining loss is rule 3, whose population is a genuine C1/C3 mixture on every split.

The three thresholds (>2, >2, >2.5°) and the rule order were fitted on the 567-case training residual pool only, by a Gini decision tree (analysis/fit_magnitude_rule.py), and have not been retuned since. The four exact criteria — 1 km, 3 PCI changes, 40 km/h, 160 RB — are given by the task and were never fitted. Nothing is applied by code at inference time: the thresholds are written into the prompt as domain knowledge and the model applies them.

The model then writes one verification line per exact criterion — field name, both numbers joined by a signed inequality, verdict word. This exact shape is what layer 2 parses:

- C2: maximum_distance_km (analyze_coverage_geometry) is 0.081 < 1 → not triggered.
- C5: transition_count (analyze_mobility) is 1 < 3 → not triggered.
- C7: maximum_speed_kmh (analyze_mobility) is 33 < 40 → not triggered.
- C8: low_throughput_rows_mean_scheduled_rbs (analyze_radio_resources) is 181.8 > 160 → not triggered.
No exact criterion fires → residual case. Had one fired, that class would be the answer and the pipeline would stop here — that is the fast path, 56.5% of cases, and it is 432/432 correct. An automated check (assert_label_neutral) crashes the run if any tool output contains a C1–C8 token, so no tool can leak an answer.

The one limitation worth stating

C3 asserts that a neighbouring cell would deliver higher throughput here. The drive test never observes that. It records throughput for the serving cell only, so a neighbour's throughput exists in the data exclusively for stretches where that neighbour was itself serving — and in 109/109 training and 79/79 official cases those stretches are disjoint from the affected one. Signal strength is the only co-located substitute, and it is not throughput: empirically a strong neighbour is more common in gold C1 (54%) than gold C3 (44.8%), because a serving cell below its own main lobe is weak and makes every neighbour look strong.

The question is counterfactual and one drive test cannot answer it. This bounds what any system can honestly claim on these classes: near-perfect residual accuracy on TeleLogs implies outside knowledge, test-set fitting, or a different metric.
