Diagnosing 5G drive-test degradation
with LM function calling

Eight root causes, one label per case. The model may not read a verdict from anywhere: every number it uses must come from a deterministic, label-neutral measurement tool that it chooses and calls itself. This report covers what was built, what each component is worth in measured points, and — separately and in full — what failed.

The task

Each case is a drive-test table plus engineering parameters, and a question: why does throughput fall below the stated criterion on some road sections? Exactly one of eight causes is correct.

Four causes are decided by an exact criterion — serving distance > 1 km, ≥ 3 PCI changes, speed > 40 km/h, mean scheduled RBs < 160. The other four (weak far-end coverage, better neighbour throughput, overlapping co-frequency neighbours, PCI mod-30 collision) have no exact criterion and must be tie-broken from measurements.

The constraint we imposed

Six tools return measurements only. An automated check (assert_label_neutral) fails any tool output that contains a class token or a field named like a verdict, so no tool can leak an answer — not even accidentally.

Consequence: the model owns tool choice, tool order, and the decision. Nothing in the pipeline may hand it a label, including the consistency verifier, which only ever points at the model's own text.

What actually moved the number

Not prompt wording. Instruction seeds and bootstrapped demos plateaued early and stayed flat. Every subsequent gain came from mechanism: an audit-and-retry loop, a decorrelated third voter, a precision-weighted aggregator, and — largest of all — giving the hard decision its own undistracted call.

Two mechanisms that looked promising delivered nothing. Both are reported below with the measurements that killed them.

Why stage 3 exists

With all six observations guaranteed on the table and the rule order printed verbatim in the prompt, the model scored 47.9% on the 376 residual cases while a plain-Python executor of the same rules scored 76.9%. That is 109 cases lost with nothing missing but attention — the prompt was simultaneously carrying four gate criteria, eight cause definitions and the full drive-test table. Splitting the decision out recovered most of the gap.

Accuracy by attempts consumed

Cost by attempts consumed

A case that clears the audit immediately is 97.4% correct for 10.4 s. A case that exhausts all three attempts is 47.3% correct for 38.5 s and 19.4 LM calls. Retrying the same program does not rescue a hard case; the compute should change mechanism instead — which is exactly what stage 3 does.

Quality per unit cost

The cascade trades 1.4 points for 58% of the serial cost and needs no tuning — the routing rule has no free parameter. The single-program pipeline is better still: higher on the selection set at 45% of the ensemble's LM calls.

Where the wall-clock goes

The thinking ballot alone is about two thirds of the ensemble's serial time and carries the widest variance (±4.6 points draw to draw). Removing it is the single biggest cost lever, and the specialist pipeline does exactly that.

Method and statistical discipline

Splits

  • dev-96 — 12 per class, hash-split from the training pool. Used for selection.
  • sel200 — 200 further training-pool cases, past the window the demo bootstrapper drew from. Added in round 4 after dev-96 selected noise three times.
  • holdout-96 — untouched confirmation set.
  • official-864 — the frozen test file. Every run against it is pre-registered with its configuration before it starts.

Why selection moved off dev-96

At p ≈ 0.8 a 96-case set has 1σ ≈ ±4.4 points. Three times a change that looked decisive on dev-96 did not survive: the audit-weighted aggregator, the size of the forced-measurement gain, and the forced-measurement gain itself.

Selection now uses dev-96 + sel200 = 296 cases and every comparison is a paired McNemar test, not a difference of two accuracies.

Label neutrality, enforced rather than promised

Every tool output passes assert_label_neutral, which rejects any class token and any field named answer, label, gate, triggered, diagnosis or root_cause. The consistency verifier never names a class: each retry message quotes the model's own sentence or names a tool it skipped. The RL reward function is the only place a gold label appears, and it is never visible in a prompt. The symbolic reference is used as an audit and a ceiling, never as an answer path.

ceilingTrace-aware arbiter

113 of 147 ensemble errors already hold the gold label on a ballot. Weighting by class precision captured part of it; scoring each ballot's cited numbers against the observations is the untried remainder.

42/108 on official and 18/37 on the selection set. The 33-case overlap zone shows this needs a new discriminating measurement, not a better prompt.
