Diagnose one TeleLogs case by iteratively requesting label-neutral measurements.

The tools return deterministic measurements parsed from the raw drive-test and
engineering tables; they never return a diagnosis. Call each of the six tools
exactly once, whatever the case looks like, before writing any conclusion:
analyze_throughput_segments, analyze_coverage_geometry, analyze_mobility,
analyze_radio_resources, analyze_neighbor_overlap, and analyze_pci_relations.
Read each observation before deciding what to request next. Every number in the
final reasoning must come from a tool observation of this case; quoting a value
that no tool returned, or describing a measurement as unavailable without the
observation saying so, is an error.

The final reasoning must open with a four-line verification of the decisive
criteria. Each line must quote the measured value, then write the explicit
inequality between the measured value and the threshold, then the verdict that
the inequality implies: "triggered" when the stated condition is true, "not
triggered" when it is false.
- C2: triggered when the maximum serving distance is greater than 1 km;
- C5: triggered when the serving PCI changes 3 or more times;
- C7: triggered when the maximum GPS speed is greater than 40 km/h;
- C8: triggered when the mean scheduled resource blocks over the affected rows
  is below 160.
A triggered criterion IS the diagnosis: stop and answer that class. If several
lines are triggered, the earliest listed line wins. Writing a measured value
whose inequality makes a criterion true and then labelling it "not triggered",
or selecting a different class after a triggered line, is an error. No
qualitative narrative can override a verified decisive criterion. Only when all
four verdicts are "not triggered" may the analysis continue below.

Next check the sufficient C1 witness: an affected row whose UE elevation is
below the main-lobe lower edge AND whose serving RSRP is at or below -90 dBm
proves C1; quote that row's elevation, lower edge, and RSRP.

If there is no such row, write a second verification block of four lines, each
quoting the measured values from the corresponding observation:
- segment advantage: the affected segment's minimum throughput, the best other
  serving segment's minimum, and their difference (alternative minus affected);
  with a single serving segment the advantage is undefined;
- overlap: the best non-colocated neighbor gap (neighbor minus serving, dB)
  listed by analyze_neighbor_overlap on an affected row;
- collision: whether analyze_pci_relations lists an affected row whose serving
  and neighbor residues mod 30 are equal, quoting both residues;
- geometry: whether an affected row's UE elevation is below the main-lobe lower
  edge, quoting elevation and edge.
Then select by the first rule whose quoted measurement is satisfied:
1. segment advantage of at least 142.5 Mbps selects C3;
2. otherwise a non-colocated neighbor gap of -3 dB or better selects C4;
3. otherwise an equal pair of modulo-30 residues on an affected row selects C6;
4. otherwise an affected row below the main-lobe lower edge selects C1;
5. otherwise select C3.
This order is a calibrated tie-break over the quoted measurements only; it
never replaces measuring, and skipping any line of either verification block is
an error. Close by citing the decisive rows and values and select exactly one
class.
