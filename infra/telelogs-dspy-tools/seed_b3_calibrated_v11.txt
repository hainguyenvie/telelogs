Diagnose one TeleLogs case by iteratively requesting label-neutral measurements.

The tools return deterministic measurements parsed from the raw drive-test and
engineering tables; they never return a diagnosis. Every number in the final
reasoning must come from a tool observation of this case; quoting a value that
no tool returned, or describing a measurement as unavailable without the
observation saying so, is an error. Comparisons must be written as signed
inequalities between the two numbers, never as words like "worse", "weaker" or
"better"; remember that for negative numbers -2.1 > -3 and -95 < -90.

Stage one. First call exactly these four tools, one call each:
analyze_throughput_segments, analyze_coverage_geometry, analyze_mobility, and
analyze_radio_resources. Then verify the four decisive criteria, one line per
criterion. Each line must quote the named observation field, write the two
numbers joined by < or >, and state the verdict: "triggered" when the stated
condition is true, "not triggered" when it is false.
- C2: triggered when maximum_distance_km (analyze_coverage_geometry) is
  greater than 1;
- C5: triggered when transition_count (analyze_mobility) is 3 or more; a count
  of exactly 3 already triggers;
- C7: triggered when maximum_speed_kmh (analyze_mobility) is greater than 40;
- C8: triggered when low_throughput_rows_mean_scheduled_rbs
  (analyze_radio_resources) is below 160.
A triggered criterion IS the diagnosis. Stop at the first triggered line: do
not call any further tool, do not discuss other causes, answer that class with
the four verification lines as the reasoning. Writing a measured value whose
comparison makes a criterion true and then labelling it "not triggered", or
selecting a different class after a triggered line, is an error. No
qualitative narrative can override a verified decisive criterion.

Stage two, only when all four verdicts are "not triggered". Check the
sufficient witness for C1: a row listed in rows_below_main_lobe_lower_edge
(analyze_coverage_geometry) whose throughput is below the stated criterion AND
whose serving RSRP satisfies RSRP <= -90 proves C1; write the signed
inequality (-93.1 < -90 satisfies it; -88.9 > -90 does not). If no row
qualifies, call analyze_pci_relations and analyze_neighbor_overlap, one call
each; writing any residual conclusion without both observations is an error.
Then check these rules one at a time, in this exact order, quoting the named
observation field:
1. minimum_difference_mbps from segment_minimum_comparison
   (analyze_throughput_segments) of at least 142.5 selects C3; undefined when
   the drive has a single segment;
2. otherwise a non-empty equal_residue_pairs from analyze_pci_relations
   selects C6;
3. otherwise a best_noncolocated_gap from analyze_neighbor_overlap of -3 dB or
   stronger, meaning gap > -3 or gap = -3, selects C4 (null means no
   non-colocated neighbor);
4. otherwise a low-throughput row listed in rows_below_main_lobe_lower_edge
   selects C1;
5. otherwise select C3.
Exactly as in stage one, stop at the first satisfied rule: it is the
diagnosis, and later rules must not be evaluated or mentioned. Selecting a
class whose rule comes after the first satisfied rule is an error. This order
is a calibrated tie-break over the quoted measurements only; it never replaces
measuring. Close by citing the decisive rows and values and select exactly one
class.
